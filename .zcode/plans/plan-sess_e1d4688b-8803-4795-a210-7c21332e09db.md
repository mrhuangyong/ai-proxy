# 修复桌面端 401（残留 server 进程端口冲突）

## 根因
我昨晚调试遗留的 nohup 进程 `ai-proxy-server`（PID 91921，server 模式 + JWT 鉴权）占着 `127.0.0.1:7860`；桌面 app 绑 `0.0.0.0:7860` 与之静默并存，回环流量被它截走 → 桌面 UI 全量 401。桌面免登录逻辑本身完好。

## 修复步骤（1 分钟）

1. **终止残留进程** `kill 91921`（我启动的调试进程；7860 随即由桌面 app 的通配监听自然接管，代理功能不中断——tauri dev 的桌面二进制 22:30 构建，已包含昨晚全部修复：/v1/models codex 元数据、converter 各项修复）。
2. **验证桌面端恢复**：`curl http://127.0.0.1:7860/api/...`（如 providers 列表）确认不再 401；浏览器刷新 `http://localhost:1420` 页面正常。
3. **验证 codex 链路**：`curl /v1/models` 确认 codex 元数据（slug/shell_type）仍在（桌面 app 的 server 在响应）。

## 顺带说明（不强制处理）
- 还有一个已安装的生产版 `/Applications/AI Proxy.app`（PID 26007）在运行，当前没占 7860，不影响本问题；为绝后患可一并退出，但需你确认（它是你手动开的）。
- 可选防御性改进（本次不做，需要的话另开任务）：桌面 app 启动后对 `127.0.0.1:port` 做一次 `/api` 自检，发现响应头带 JWT 401 特征即弹窗提示「端口被其他 ai-proxy 进程占用」，避免此类静默冲突再排查半天。
