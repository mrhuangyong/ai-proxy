# codex 模型选择器修复（实验 + 兜底）

## 背景（已实证的根因）
- codex /model 选择器当前只显示 `~/.codex/models.json`（config.toml `model_catalog_json` 指向）的内容——该文件今早 09:53 配置"ZAI 直连智谱"时创建，只有 glm-5.3-flash 一个条目，自定义目录整体替换了 codex 内置目录。与本次 AI Proxy 改造无关（codex 连的 7860 是生产旧二进制）。
- codex 26.x 的选择器是否支持从代理 `GET /v1/models` 自动发现模型：未实证（0.148 时代不支持，上游 #22160 拒改）。本次用实验确认。

## 步骤

### 1. 实验验证 codex 26.x 是否支持模型自动发现
1. 备份并编辑 `~/.codex/config.toml`：删除 `model_catalog_json = "~/.codex/models.json"` 这一行（保留 models.json 文件不动，作兜底素材）。
2. 请用户完全退出并重启 codex（ChatGPT desktop），打开 /model 选择器观察：
   - **列出代理模型**（glm-5.3-flash、glm-5.3、kimi-for-coding 等多个）→ 26.x 已支持自动发现，问题解决，收工。
   - **只列内置 gpt-\***（gpt-5.6-sol 等）→ 走步骤 2。

### 2. 兜底：把真实模型写进自定义目录
以现有条目为模板，把生产库 9 个启用模型（agnes-2.0-flash、agnes-2.5-flash、glm-5-turbo、glm-5.3、glm-5.3-flash、k3、kimi-for-coding、qwen3.6、qwen）写入 `~/.codex/models.json`（slug/display_name/visibility="list"/context_window 取 provider_models 表值，glm-5.3-flash 排第一保持默认），并在 config.toml 恢复 `model_catalog_json` 行。重启 codex 验证选择器列出全部模型、可选中对话。

### 3. 收尾
- 无论哪个分支，把结论（26.x 是否支持 /models 自动发现）更新进项目记忆 codex-model-selection-root-cause。
- 提醒：codex 当前连的 7860 是生产版（旧代码）；要体验本次多协议/透传新功能，需从 dev 实例（17861）启动 codex 再验证。

## 涉及文件
- `~/.codex/config.toml`（删/恢复一行）
- `~/.codex/models.json`（兜底分支才改写）
